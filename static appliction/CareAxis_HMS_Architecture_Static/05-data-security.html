Access boundary requirements

AuthenticationProduction users must have verified identity and managed sessions.
Role-based permissionsEnforce permissions on the server, not only by hiding UI controls.
Hospital and branch isolationScope every record request to authorised facilities and patients.
Audit historyRecord sensitive reads, edits, approvals, exports and failed access.
Data protectionUse encrypted transport, appropriate storage encryption, backups and retention controls.

Static prototype limits

No authentication, database, tenant isolation or audit service is implemented in this static app.
  • Sign-in only routes to the selected role.
  • Saved entries are browser-local and not shared across devices.
  • Sample patient and operational records are illustrative.
  • Do not enter real patient data or use for clinical decisions.
  • Production release requires security, clinical safety and compliance review.
